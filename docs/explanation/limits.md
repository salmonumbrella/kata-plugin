# Limits

The plugins track todo plans, OMP delegates, inherited Pi child processes, and local or remote Claude Workflow runs. Kata's accepted close records determine completion. Local todo plans and pending close retries are saved in harness session entries and restored on resume.

- **Claude workflow contributor identity — host API.** The tested function-hook API exposes a Workflow run and its terminal task notification, but no reliable spawn/compose join for each contributor. One issue is tracked per run; individual workflow agents cannot receive a plugin binding and contract through that API. **Upstream ask:** expose contributor spawn identities, writable prompt context, and final receipts joined to the run/task ID. A native task-UI mirror also needs a supported task mutation API.
- **Remote workflow verification — host API / by design.** `remote_launched` provides `taskId`, `taskType: remote_agent`, `workflowName`, and a cloud session URL; it has no local `runId`. Terminal task notifications update the run's Kata issue. Remote file paths and verification claims do not establish proof for the local checkout, so remote completion leaves open work for review unless Kata already accepted an independent close. **Upstream ask:** expose remote commits/PRs and verified contributor receipts with repository identity, so remote evidence can be attributed without treating remote paths as local reviewed paths.
- **Delegate discovery — host API.** OMP matches a delegation to a plan task by name, ref or word overlap, and to the active task only for an explicit current-task handoff; Pi does the same after inheriting `KATA_PI_PARENT`. Pi does not expose a general child-process spawn/join hook. Processes launched with a replaced environment, from another machine, or before parent startup finishes must receive an explicit binding. The native Pi attention registry is used to retain the parent's baseline before clearing inherited `KATA_REF`; compatibility is verified against the generated native adapter. **Upstream ask:** provide stable child identity, environment handoff, lifecycle receipts, and a public native-attention baseline API.
- **OMP native harness — Kata CLI.** Kata has no omp harness: `agent-hook contract omp` and `attention-native omp` are rejected, and `agent-hook install` has no omp target. The omp plugin passes `pi` to `attention-native`, which only selects payload parsing and the session token. **Upstream ask:** an `omp` harness for `attention-native`, `status` and `install` (user scope `~/.omp/agent/extensions/`).
- **Shell attribution — by design.** Recognized standalone Kata commands receive the delegate's teammate; actor impersonation with `--as` is refused. Dynamic aliases and opaque embedded scripts must use the supplied binding command themselves. Lexical rewriting is not a security sandbox.
- **Observation and proof — host API / by design.** Claude tool observations cannot audit opaque programs' filesystem side effects. Missing receipts, unknown writes, failed checks, or incomplete reports can leave finished work open for review. Idle alone is not completion. **Upstream ask:** provide authoritative write-path and terminal verification receipts for opaque tools and delegated writers.
- **Session retention — host API / by design.** Durable OMP/Pi state requires a saved session and its custom entries; ephemeral sessions, deleted session files, or host compaction that discards those entries cannot restore local plans or retry queues. Claude may compact inactive settled sessions above 2 MiB; active state can reach the host's 4 MiB store limit. **Upstream ask:** preserve extension state across compaction and provide a larger durable state store with retention guarantees.
- **Outages and concurrent writes — Kata CLI.** Foreground hooks have bounded budgets. Outages are quiet and retryable, not proof that tracking succeeded. Concurrent external writers can race comments because Kata has no comment idempotency key. Guarded multi-key attention updates can partially succeed before a conflict; reopen has no atomic CLI guard. **Upstream ask:** add comment idempotency, atomic multi-key metadata updates, and revision-guarded reopen. Existing ownership/revision checks preserve conflicting writers' changes.
- **Abrupt termination — host API.** Graceful child shutdown can mark unfinished work for review; a crash or SIGKILL cannot run shutdown hooks. Saved retries resume when the harness session is reopened, rather than through an always-running background worker. **Upstream ask:** provide durable lifecycle delivery or launcher cleanup for terminated sessions.
